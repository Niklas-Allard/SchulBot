Was implementiert wurde

  Laravel Web-App (web-SchulBot/)
  - 4 neue Migrations: role in users, bot_configs, command_history, processed_messages              
  - Models: BotConfig (verschlüsselte Passwörter via Laravel Crypt), CommandHistory, User-Relationships
  - Controller: DashboardController, BotConfigController, CommandHistoryController, AdminController,
  InternalApiController
  - Routes: /bot/setup, /bot/history, /admin/users, /api/internal/bot-users
  - Vue-Seiten: Dashboard (Stats + letzte Befehle), Bot Setup (IMAP/SMTP/AI-Formular), Verlauf (Tabelle mit
  Paginierung), Admin (Nutzerverwaltung + Stats)
  - Sidebar mit konditionellem Admin-Menüpunkt

  Go Bot (bot/)
  - internal/users/manager.go — lädt User-Configs von Laravel API
  - internal/app/multi.go — Multi-User-Runner mit einem Goroutine pro Nutzer
  - internal/app/app.go — Key-Scoping für BoltDB (user:{email}:)
  - cmd/server/main.go — automatisches Multi-User-Mode wenn LARAVEL_API_URL gesetzt
  - Single-User-Modus (Legacy-.env) bleibt vollständig erhalten

  Docker (C:/dev/SchulBot/)
  - docker-compose.yml — web + bot Services
  - web-SchulBot/Dockerfile — Multi-Stage: Node (Vue Build) → Composer → PHP 8.4 Apache
  - docker-entrypoint.sh — SQLite erstellen + Migrationen beim Start
  - .env.web.example / .env.bot.example

  ---
  Nächste Schritte zum Deployen:
  # 1. Env-Dateien anlegen
  cp .env.web.example .env.web   # APP_KEY + BOT_API_SECRET setzen
  cp .env.bot.example .env.bot   # gleichen BOT_API_SECRET setzen

  # 2. Starten
  docker compose up --build

  # 3. Ersten Admin setzen (einmalig)
  cd web-SchulBot && php artisan tinker
  # >>> App\Models\User::find(1)->update(['role' => 'admin'])

  # 4. npm run dev (lokal, einmalig für Wayfinder-Routes)
  cd web-SchulBot && npm run dev
